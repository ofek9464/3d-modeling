# Artifact quality repair

Use this after rejected output or a failed quality check. Preserve the accepted baseline and capture the smallest evidence set showing the defect: feedback, relevant objects, source images and a render, overlay, contact sheet or report.

Identify the failure in geometry, source consistency, texture mapping, surface coverage, look, animation or export. Make one evidence-based hypothesis and use the relevant existing module to test it. Repeated failure calls for a new diagnostic method or upstream correction, not another blind rebuild.

Apply the smallest authorized correction, recheck its affected evidence and continue until the requested bar is met or a concrete limitation prevents progress. Record source conflicts and use an already agreed canonical policy. Do not modify unrelated assets or hide geometry errors with lighting.

Use scripts/ralph_autoloop_plan.py to classify feedback and suggest a repair plan. The output is diagnostic guidance, not authority for extra actions. Completion means the repaired artifact meets its applicable checks, or its remaining limitation is documented honestly.

Developing the skill library is separate: read [skill maintenance](references/skill-maintenance.md) only when the user requests it. Repairing an artifact does not require skill patches, sanitization reports, version changes, commits or releases.
